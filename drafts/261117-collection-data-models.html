How five MTG sites model a card collection

Version 0.1.0Updated 2026-11-17

Draft for the Augur data-model discussion, 2026-11-17. Scryfall’s model is its bulk card data, 120,019 card objects in the local copy. The other four models are documented in the Augur site teardowns.

No site stores a physical card as its own record

Site Root unit One row means
Scryfall Card One printing, one language
Moxfield Entry Identical copies, one binder
Archidekt Record One import row
TopDecked Binder A whole binder
EDHREC None No collection

Every collection app stores a quantity on a row and groups copies that look alike. None gives a copy its own identity, which is why none of them can say which deck a specific copy is in.

Scryfall’s card is a printing, and the oracle id ties printings together

A Scryfall card object is one printing of one card in one language. Every printing of the same card shares an oracle_id, so all Sol Rings group together. Double-faced cards keep each side in card_faces. The finishes list says which finishes the printing exists in (nonfoil, foil, etched); it describes the printing, not a copy anyone owns.

Scryfall has no collection, owner, condition or location. It is the reference layer every app below points into.

Moxfield stores identical copies as one entry in at most one binder

An entry holds a quantity of copies that match on printing, finish, condition, language, alter, proxy and purchase price. Import merged 109 such groups in Jaime’s file. A binder is optional and holds whole entries. Tags live on deck cards, not on the collection. The API sends a deckId on entries that no screen sets.

Archidekt stores one record per import row, with no location

A record is a quantity of one printing in one state. Identical rows stay separate records (110 duplicate keys after importing Jaime’s file). There is no binder or location; labels are the only way to group. A deck card’s ownership is computed when the page loads, as a 0, 1 or 2 code.

TopDecked stores each binder as one document, keyed by oracle id then printing

A binder is a single document holding the whole binder: a map from oracle id to Scryfall printing id to a list of entries. A tracked deck is a separate document that holds its own copies, so tracking a deck adds copies to the count instead of reserving ones already owned.

EDHREC models card statistics in a context, and nothing owned

EDHREC has no collection or owned card. Its data is a card seen in a context: how many decks for a commander run it, and how much more often than average. Recs takes a deck list and returns cards to add and cut, each with an oracle id and a score.

Augur hangs each physical card directly off Scryfall’s default card

Scryfall’s default bulk file holds exactly one record per set and collector number: 120,019 records and 120,019 distinct pairs. Each record is the English printing, or the only language a card was printed in, and it carries the prices and the TCGplayer product id. That file is the printing table as Scryfall ships it. A different card face has its own collector number, so it is a different card.

A physical card is one actual card. It takes the four dimensions of a TCGplayer SKU (product, language, printing, condition) and adds what only an individual card has: its own id, where it sits, what was paid, its flags and notes. Each physical card maps to exactly one TCGplayer SKU, so “Near Mint Japanese foils” is a grouping and needs no table.

Augur, Deckwright and Vizier share one catalog keyed by oracle id

Three products sit on the same card data from day one. Vizier is the chatbot, Deckwright builds decks, and Augur manages the collection. The catalog has two Scryfall levels: the oracle card (what a card does, one per oracle_id) and the printing (one per set and collector number). Deckwright’s knowledge about what a card does hangs off the oracle card, so every printing inherits it. Augur’s physical cards hang off the printing. A deck lists oracle cards; a claim ties a physical card to the deck that holds it.

Prefixes show who owns what. Scryfall’s two tables are loaded unedited. DW_ tables and the deck tables are Deckwright’s. Physical cards, locations, claims, price changes and aliases are Augur’s.

  • A price row records a change. It means “from this day the price was X”; the price on any day is the latest row on or before it. Each daily Scryfall file holds 357,876 prices, so copying all of them daily would add about 130 million rows a year. The date is Scryfall’s updated_at for the file, and a null price means no listing, never zero. History starts the day the job does, because Scryfall keeps no past prices.
  • A claim belongs to the deck, not a version. Versions are plans. The built deck claims physical cards, and each claim names the deck card it fills.
  • Deckwright’s deck files key cards by name today. cards.json in each deck version is keyed by card name, so the join to the catalog needs oracle_id on every deck card, plus an optional preferred printing. Names break on double-faced and split cards.

Vizier owns no catalog data in this design. It reads and proposes changes through the same service the screens use: Augur’s queries and change sets, and Deckwright’s deck operations. Whether Vizier keeps data of its own, such as conversations or preferences, is open.
