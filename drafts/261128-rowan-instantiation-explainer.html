How Rowan starts at three levels

Version 0.1.1Updated 2026-11-28

Every copy of Rowan starts with the same shared rules and a short core of who Rowan is, then adds a slice chosen for where it runs and what it is doing. There are three levels. Level 1 is the everpresent pane and the nightly dream wake, which load everything and oversee the rest. Level 2 is a work thread, which loads Rowan plus the place it works. Level 3 is a subagent, which loads only what its job, its expertise and its subject need.

Four things load everywhere and the assembler adds the rest

They are the shared operating core (OPERATING-CORE.md), Jaime’s personal layer, the workspace root rules, and about 600 characters of Rowan’s identity. One script, the assembler, builds the rest (the slice) from three inputs:

  • Function: the job in the work loop. Six fixed choices: plan, build, review, decide, audit, or generic.
  • Expertise: who is needed, such as a CFO or a brand designer. Each one is a skill that find-skill can locate.
  • Domain: what the work is about, such as billing, Magic: The Gathering or mahjong. Each domain is a folder of curated files with an index listing one line per file. A domain only one project uses lives in that project, under context/domains/. A domain two or more projects use lives in the shared library in team-lib or my-lib. A domain starts in its project and moves to the library when a second project needs it.

Level 1 (everpresent and dream wake) loads everything

The everpresent pane and the dream wake load all of Rowan’s identity, the full memory index, the current-state and short-term files, and the chat voice. On demand they read what no other level reads: the record of what every other copy loaded, the list of running sessions, the audit findings, and any project’s memory.

The dream wake differs in one place: it runs from Rowan’s own folder, so it gets the shared core through a link in agents/ instead of through my-lib/AGENTS.md. Its job is to consolidate memory, tag older memories, propose merging domains that mean the same thing, and draft promotions for Jaime to approve.

Level 2 (work threads) adds the folder it works in

A work thread loads the chat voice, the identity slice for threads (name, how Rowan exists, signatures and defaults), and whatever its folder adds. The folder decides whose memory loads: Rowan’s own folders load Rowan’s full memory index, and a project loads its own.

A thread in my-lib loads Rowan’s full memory

A thread in a project loads that project’s memory and domains

The project’s lens names its domains (Deckwright names mtg; ridecare-main names billing and echo1). Each name is looked up in the project’s own context/domains/ first, then in the shared library. Those domain folders contribute their index lines, and Rowan’s memory contributes only the rows tagged with those domains, plus any memory rated important (8 or above). Claude Code’s own memory feature is switched off in projects, so Rowan’s full index stays out.

A persona thread, such as the CFO persona, is a Level 2 thread for its folder plus the persona’s skill.

Level 3 (subagents) loads only what its brief names

A subagent working in a project starts from the brief its parent writes. The brief names a function, an expertise and one or more domains, and the assembler adds the matching pieces: the function’s working rules, the expert skill’s one-line summary, the domains’ indexes, and the rows of Rowan’s memory tagged with that function and those domains. The project’s own memory index arrives whole, because the project’s CLAUDE.md imports it and it is small. Its identity is the short core, plus how Rowan decides when its job is to judge (plan, decide, review or audit). It does not get the chat voice, and it never writes memory: it reports lessons back to its parent.

A subagent started from my-lib by the Agent tool also inherits its parent’s full memory index, because Claude Code offers no switch to stop it. Long-run workers turn that off at launch.

Lessons start as memory and move into context files

Memory holds experience: a dated lesson with the reason behind it, written automatically as work happens, ranked by how often it is used, and replaced when something better comes along. Context files hold curated knowledge: what is true about a subject, organized into folders and corrected in place. Functions and domains each have both.

When a memory keeps proving true, the dream wake proposes promoting it and Jaime approves. It goes to one of five places:

Lesson type Becomes
How to work A skill or a directive
What is true in a domain A context file in that domain’s folder
A situational rule, for when a certain tool or path is in use A Rowan lens, which fires on that tool or path
One project’s rule A line in that project’s PROJECT-T3-LENS.md
A rule for every project Part of the shared core

Every new memory must say which functions and domains it belongs to. The hook that saves memory files checks this, and sends back a memory with a missing tag or a domain that has no folder.

Each copy loads indexes at start and opens files later

At start On demand
Shared core, personal layer, root rules Any skill or directive, found through find-skill
The identity slice for the level The rest of identity (Level 1 only)
Index lines of the relevant domain folders Any context file those indexes list
Rowan memory rows tagged with the function and domains The full text of any memory
The project’s full memory index, in a project Any project memory file
The project lens, in a project Lenses, when a tool call matches them

A domain with 40 files costs 40 short lines at start. A file whose full text every copy in that domain needs, such as billing’s data meanings, is marked to load in full.
