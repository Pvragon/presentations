1. One page: one recursive node replaces the run, done is a frozen matrix version, and code forces the reframe

What changes. A v0.4 run is a flat queue under a CEO who judges its own convergence. v0.5 uses one primitive at every level, the node: a frame slice, finite exit tests, a budget and one procedure (Test-Recognise-Split-Commit, TRSC), done when its own tests pass. Nodes form a persistent tree per product. Levels 1 to 4 of Jaime’s ladder form the frame, written breadth-first and capped; level-5 tasks are decomposed as work meets reality. Done for release N is coverage-matrix version N; one walk runs before acceptance. A code governor and each node’s budget rule escalate to an independent decider whose verdict binds; only the daemon records protected rulings. Every session starts from a role pack and a domain pack that code assembles. Run tokens fall in three buckets; coordination is capped at 20-40% (Jaime) and a code signal, G6, watches it.

Why. On the eleven v0.4 runs of 10-30 to 11-06, second-pass rework took most of the spend (261106-lr04-week-watch/SYNTHESIS.md s2): strength spent 87% of component tokens on 112 reopens; finish built 15 subprojects in 5.3 h, then reworked for 34 h; no pass managed the architecture (CO-01). Root causes: done held an open critic; every fix re-ran the new-work pipeline; later scope joined the queue unframed; the CEO judged its own convergence (F-03).

What it fixes. All 105 inventoried failures map to a mechanism or “not addressed” with a reason (s13). A replayed governor fired 11 to 19 h before anyone noticed (s5.4); thresholds are unfitted. Coordination is an estimated 29% of a level-1 run at central assumptions, 17% with the limits adopted here (s5.7), against 33% to 55% measured on v0.4.

2. The node primitive: frame slice, exit tests and budget, run through TRSC

2.1 Anatomy

Field Content
id, level, order Identifier, ladder level 1 to 5, position among siblings.
goal, why The goal, and the parent objective it serves (Keeney).
frame_slice Capabilities, contracts and rulings touched; only the ancestor tests its outputs feed.
exit_tests Finite, mechanical or for a named judge; each names the capability or contract it verifies.
budget Tokens, active hours, money; 2x the estimate until a reference class exists (proposed).
state open, running, replanning, done.
children The committed child, fully specified, plus one-line stubs.
status_line 40 words: tests passing, top failing classes, spend, escalations. A board row.

A node is a record on disk. A product’s nodes form one product tree in the product’s repository, kept across runs (M25). longrun start takes a product and a node, never a plan file, so later work always has a root to re-enter. A brief carries the frame slice and packs, never a transcript.

2.2 TRSC, one procedure at every level

From research-goal-decomposition.md (TOTE, Soar, ADaPT, ReCAP).

  1. Test. Run the exit tests; all pass is done. On first entry, freeze goal, why, tests and budget. This is strategic planning and always runs.
  2. Recognise, in code. A node the plan marks as a leaf (a skill, a prior method or one owner), and every red cell of a node that has an owner, goes straight to an owner with the cell and the frame slice. No Claude call.
  3. Split (no leaf is marked, or an owner’s attempt leaves the same cells red, which the budget rule sends to rung 2). Children come from failing tests. Code checks the WBS 100% rule, at most about 5 children, one parent integration test, and that each child names a frame capability.
  4. Commit. Specify only the next child; siblings with disjoint files and frozen inputs may run in parallel.

2.3 Frame eager, tasks lazy, and the frame’s size budget

DIRECTION s4: levels 1 to 4 split eagerly at Test; level-5 tasks split only on impasse. Eager is not deep: levels 1 to 4 go only far enough to name every capability, data source, central process and contract. Caps (proposed): frame about 300 lines; about 12 capabilities of about 15 lines; contracts as interface signatures. Intake refuses a frame over budget, in code (v0.3’s specs grew sixfold in a day).

2.4 Rules the node carries

  • Done is its own tests. Closed children under a failing parent test yield one new child per failing test. Integration is the parent’s exit test.
  • Fix path. Code routes a failing test to its node’s owner with the test and the frame slice: no spec rewrite, no routing session.
  • Budget rule, the single stuck trigger: spend past budget, or 2 cycles (fix wave plus matrix run) with no new test passing, triggers rung 2. Estimates include spec time and real capacity (F-25).
  • Planning rules, prompt text at level 1: real data first, with performance and subset-rerun tests (F-17, F-30); commit order respects frozen inputs (F-35); one owner per file; code on fixtures; FS, SS, FF or SF timing; never drop a node owning a matrix cell; a report is not an exit (F-96).

Diagram 1: node anatomy: brief assembly with packs, Recognise in code, eager at levels 1 to 4, lazy at level 5, and re-entry by the decider’s verdict. Colors: purple is Jev (a closed question), orange a Claude session (open judgment), blue deterministic code, white a record or a person.

3. The frame holds the whole: brief slices, split checks, a decider checklist, pull-up and an architecture pass

Ruling 1: someone must hold the whole vision. The CEO’s memory failed at it, so the frame holds it:

  1. Every brief carries the frame slice (M1).
  2. Every split is checked in code (M2): each child names a capability; each test names the capability or contract it verifies, so a frame change flags only the tests on what changed (F-82).
  3. Decider checklist mode (M4). On every release, every 8 active hours (proposed) and in every reframe verdict, the decider answers a checklist that can fail (every capability serves the want; every red class has an owner; no contract changed outside a ruling; the frame is in budget). A failed item is a rung-4 trigger.
  4. Pull-up (M3; ruling 2). When red cells share a class key (Deckwright: the effect-class row) at 3 or more places in at least 2 nodes (G4), code moves the fix to the lowest node owning that class. No owner is a rung-4 trigger: the decider adds the central process (“Forge construct encoding”).

The architecture pass (M5; ruling 9). Every pass at levels 3 and 4 starts from the modules, one contract per pair, and where each kind of interpretation may happen; a product translating an external format inventories its whole construct set at intake. Exit tests, because an instruction alone failed (CO-01): each kind of interpretation is owned by one module (import-graph or grep check); every census construct maps to an owning node. Close-out had 98 of 138 trigger modes unnamed and ~130 regex sites on card text. Every level-3 and level-4 architecture test runs on every landing, level 5 included, in the merge queue at zero tokens, so a leaf that adds a regex on card text fails at once (PR3-4); the gate reviewer adds LLM judgment only on level-3 and level-4 landings.

Contracts without pinning; adapters with a deletion test. Contracts are signatures frozen as children’s exit tests (F-21), unversioned, since pinning means two live implementations (F-15). A producer lands with every consumer’s tests green, or, for many consumers (the card schema has eight, F-11), behind a temporary adapter whose architecture child exits only when “the old interface has zero callers” (grep).

Sign-off. Jaime signs frame levels 1-2 at launch and on expansion in his runs (s3.1); the decider signs 3-4 against the register before spend (F-84).

3.1 Requests and expansion: the CEO proposes, the decider classifies and picks the node

A request, from Jaime or the CEO, is a proposal: the CEO may suggest a class and a node, never decide them (M10). One decider session classifies it and picks the re-entry node from code evidence: the capability ids it touches (M2), their lowest common ancestor, and whether it needs a new capability.

Class What it changes Re-entry node Ruled by
Priority change order only (code-enforced; budgets are threshold rulings) none decider classifies; CEO writes order
New scope cells under existing capabilities; may reframe levels 3-4 lowest common ancestor of the capabilities touched; its architecture tests re-run decider; 10% scope budget (s4)
Expansion the want or a capability (levels 1-2) owner of the highest changed level, usually the root rung 5, then s3.2

The task list is a derived view of the tree’s frontier, so there is no queue to append to (F-34).

An expansion is rung 5. In Jaime’s runs the CEO shows the level-1 and level-2 diff and the daemon records his typed reply (s5.2) before any spend; only the new scope waits, and an unanswered diff goes to his digest. In the ultra-long category Rowan rules via the decider path (level 3).

3.2 Expansion re-entry: re-test first, keep history

Finish copied strength’s boundaries and never asked whether X’s architecture fit X+Y+Z (F-14, F-11, F-28). In v0.5 “do Y and Z” re-opens a node of the same product tree (M24, M25). expand runs only on a decider classification and refuses a CEO-issued call or a node with an active governor signal (replanning, cooldown, an unresolved trigger, a pending verdict or hold), so an expansion cannot silence a governor. The strategic planner re-runs Test:

  1. Ground on the built code and data as they are now, not the old plan.
  2. Re-test, then rewrite only what fails. Re-run the architecture exit tests and capability checks against the X+Y+Z goal and census. A passing part keeps its ids (F-82); a failing architecture test makes an architecture change the first child. The rulings register carries over (F-84).
  3. Matrix. X’s accepted cells become regression cells; queued N+1 cells enter first, then Y and Z (F-36). Expansion scope has its own decider ruling, apart from the 10% scope budget.
  4. History carries. Signal windows and spend carry; only new nodes start fresh.
  5. Sign-off as at launch: levels 1-2 by the rung-5 ruling, 3-4 by the decider.

3.3 Context packs: every call gets a role pack and a domain pack, assembled in code

The staged-thinking study (../../sources/summaries/2610-internal-staged-thinking-study.md, 14 episodes) found that success tracked the domain’s own intermediate levels (Waystar: GET, CLEAN, ANALYZE, PUBLISH; Deckwright: Commander, Strategy, Pool, Deck, Tune); a generic breakdown failed (F-13, F-19, F-20). So every Claude call’s context has these layers (M26):

Layer Holds Reuse Built by
Core AGENTS.md, lenses everywhere exists
Role pack how to do one kind of work: software architecture planning, coding, data and finance analysis, research, strategy, marketing, law, design a small universal set curated once
Domain pack the single source of the domain’s structure and rules: natural levels (the Split template), lens ids, the oracle style, reference budgets across projects in the domain starter pack at intake; promoted from projects
Grounding store only this project’s facts and sources, retrieved per brief; links to pack entries, never copies them one project intake’s Ground step

Packs are keyed by role times domain. The strategic planner tags each capability with a domain at intake, signed with the frame; the daemon assembles every brief from the node’s role and domain tags through a pack manifest (reusing find-skill); no model picks a pack at level 1.

  • Launch rule, in code, for child nodes: a child cannot start without its role pack and a domain pack. Intake’s own Ground step, and an expansion’s into a new domain, runs on the generic pack; its output is the starter pack (the strategic planner’s starter-pack mode), signed with the frame, so a missing pack never stalls intake (PR3-1).
  • Size budgets per role, in code (proposed): owner 5k tokens, node planner 10k, strategic planner and decider 15k, walker 8k; CEO and gate reviewer 8k. The assembler slices the domain pack to the node’s capability tags, emits role pack, sliced domain pack, then node text, byte-stable so it is served as a cached prefix, and refuses an over-budget pack as intake refuses an over-budget frame. Owners run about 38 turns, so slicing saves most.
  • Promotion is a move: after an accepted release, what the grounding store learned that holds beyond the project moves into the domain pack, and the grounding entry becomes a link to it. Packs cite lens ids; each lens loads once. A promotion over budget replaces, never appends. Between runs only, as one versioned change (s8).
  • Frozen across level 1: the three level-1 runs share one pack set. Any change between them is a recorded parameter change, evaluated like any other (s8).
  • Level 1 needs four packs: role packs for software architecture planning and coding, a generic default, and the MTG domain pack for Deckwright.

4. Done is matrix version N; one walk runs before acceptance

Ruling 3: done is a frozen executable condition; walks are discovery.

The coverage matrix (M7): one cell per effect class times modifier (Deckwright), real cards and judge rulings as oracle. A cell is data (input, expected result) run by a runner the interface’s node owns, so a refactor changes runners, never the protected expected results. One check, one owner, local assertions (198 of 252 close-out red checks were misreads; 71 were whole-pool rank checks, CO-07). Gates are named from owned files (F-05); stretch bars live in probe nodes (F-09). Done for release N is matrix version N, frozen when N’s build starts. Matrix version 1 is authored by its own planning node with its own budget: owners write cell data; the strategic planner writes only the cell schema and the class list (PR3-11).

The loop (M9): run every cell; one batched fix wave on red cells, by package, on the fix path; verify each package as it lands (F-43); end each wave with the full matrix (close-all round 6 went from 25 to 342 red without a sweep, F-42). A cell closes only if it failed before and passes after (F-07). One wave per node at a time (F-46).

Acceptance of release N (M8; Rowan’s rulings of 11-07):

  1. Matrix version N passes.
  2. One walk runs on N’s built artifact, uncapped, full list to a file. The daemon generates its brief from the frame; the CEO adds no text, so it cannot steer the walk (F-03). v0.4’s 5-problem cap was hit by 21 of 29 finish walks; one uncapped pass found ~157 root causes.
  3. One decider session triages the list, with the nearest existing cell per finding (code retrieval):
Finding Goes to
(a) An existing cell’s test is wrong: it passed but the product is wrong for that class Fixed in N on the fix path; corrected cells re-run in one final wave ending in the full matrix; the walk is not re-run. An architecture fix goes by pull-up, holding N for at most that node’s budget; then the decider rules accept with known failure (cell to N+1, named in release notes; never the hard part) or hold.
(b) A new class, hard part or not A top-priority cell of version N+1. Never blocks N.
(c) Which is which The decider confirms each; the CEO cannot reclassify; duplicates merge.
  1. The decider accepts N when the corrected cells and full matrix pass; never the CEO (SPEC s8).

Why done still converges. Class (a) is bounded by N’s cells, one walk’s list and the owning node’s budget; (b) never touches N. The hard part is never accepted with known failure.

Scope budget. N+1 may add at most 10% of N’s cells (proposed). No “later” bucket (72% of strength gaps went there and were never built, F-36). Overflow means the enumeration was wrong: a rung-4 trigger. Deckwright’s first uncapped walk will likely overflow it (44 hard-part problems after finish).

5. A code governor watches convergence, and an independent decider rules

Ruling 4: detect non-convergence early (target 3 hours) and force a judicious reframe.

One re-plan at a time (F-46). Rung 2 sets the node to replanning; the daemon refuses a second launch and skips its signals until the re-plan commits, plus one cycle of cooldown (proposed).

5.2 Ruling authority, enforced by the daemon

Ruling kind Author CEO

Enforcement (M12). The daemon launches the decider and is the only writer of protected rulings; the CLI refuses every protected kind from any session (A-7). A ruling by Jaime enters only as a verbatim quote from his own typed turn in the CEO log: plain-text user entries with no tool_result, toolUseResult or isMeta, minus the daemon’s own wake lines (tool output is stored as type: "user" too, 93 of 145 in one log). lr/guard.py denies tmux send-keys aimed at the CEO’s own pane. Appeals go to the same decider record; at most one per verdict, a second goes to Jaime’s daily review while the verdict stands.

5.3 Signals, defined on v0.5’s own events

Events: cycle_end, cell_red, cell_green, wave_end, walk_end, spend, verdict, ruling, appeal. Signals are ratios per node, computed every 30 minutes over a 3-hour active-clock window (silences over 1 h cut out).

# Signal Replaces Starting threshold (unfitted) Status Rung
G1 Exit-test pass trend per node S1 flat over 2 cycles folded into the budget rule 2
G2 New-cell rate per walk, share of matrix S6 not falling across 2 releases recorded from level 1; fires from level 2 4
G3 Fix-wave yield: cells turned green over red at wave start, net of regressions S4 under 0.5 for 2 consecutive waves live 2, then 4
G4 Repeat-class count: red cells sharing a class key S5 3 places in 2 nodes live 3
G5 Spend against budget new past budget; 2x is rung 4 folded into the budget rule 2, then 4
G6 Coordination share of run tokens, strict, cumulative after the first 10M, from bucket tags (s5.7) new notice over 30%; over 40% for 2 evaluations live notice, then 4

G1 and G5 restate the budget rule; G6 is run-wide, not per node, and reads the meter, not cells. Dropped: S2 (moved with S1), S3 (tracks run size). Any rung-4 trigger wakes the decider; rungs 2 and 3 are code. Notices go to notices.log, the board and Jaime’s daily digest, never waking the CEO (F-51). Onset: the 3-hour target counts active hours from the first wave that fails to reduce red cells, or the first walk adding more new cells than the last.

5.4 What the v0.4 backtest shows, and what it does not

governor-backtest.md replayed six old signals over 10 logs. Two-signal fires: strength at 6.5 active h (11.1 h before its first stop), finish at 5.5 (35.0 h before Jaime’s call); three more troubled runs at 5 to 12; r2-r4 missed; none on four healthy runs. S4, G3’s predecessor, fired on four of six troubled runs.

The thresholds do not carry over: fitted values sit at the grid edge, the healthy set gave 12 evaluations, nothing was held out. Level 1 refits only what gets enough data (s12).

5.5 Binding verdicts and halts

  • The decider returns continue, re-plan X, pull up to Y, or reframe level k. A reframe names the work it removes or redraws; instrument-only reframes are refused (F-80).
  • The verdict binds (M11): the daemon stops dispatching work it touches; running gates finish; untouched waves continue. A reframe’s new nodes have no history, so nothing re-fires at once.
  • Holds run on the wall clock: verdict within 1 h, the CEO’s action within 2 more (proposed); past either, the daemon notifies Jaime and relaunches a dead CEO.

5.6 Seat duties the daemon owns (M20)

A deaf CEO pauses launches (close-out ran 9.7 h with a dead CEO, F-58); every wake line is delivered (A-5). Rotation carries the live conversation (F-83, CRITICAL): the handoff holds the turns since Jaime’s last message, the open plan and unrecorded rulings, recorded first; no rotation mid-exchange. Pause holds launches, not running gates (F-104). A live ruling that changes a running gate’s tests aborts it; aborted is not a failure (F-105).

5.7 Token buckets: planning is an investment, coordination is capped

Jaime (11-07) splits run tokens three ways. The daemon tags every session at launch; no model decides.

Bucket Holds Budget
Build owners building and fixing leaves the rest
Planning investment the strategic pass, the Ground step and grounding research, node specs and exit tests at a node’s first Test, matrix-version-1 authoring, pack building 15% of run tokens, ceiling 20% (proposed)
Coordination CEO, dispatch, decider events, gate and merge reviews, retries, and any re-plan, re-spec or rework caused by a failed plan at most 20-40% (Jaime); level-1 target 30%

Planning “pays dividends” (Jaime), so it gets its own budget and is judged after each release by rework share (fix-path tokens on cells that went green to red, plus re-plans, over the release’s tokens); two releases at the ceiling with rework not falling is a checklist item. Re-planning after a bad plan is always coordination, never planning.

Each launch event carries the bucket, pack ids, hashes and token counts, prompt hash, cache mode and model. The board shows coordination strict (owner-brief packs as coordination), lenient (as build), planning, and a price-weighted share.

G6 and its levers. Over 30% is a notice to the board and digest. Over 40% wakes the decider for a binding review, with the per-row meter as evidence, choosing among levers that are legal inside a run as longrun set values within declared ranges: a cheaper model tier for a prompt, trimmed packs (budgets only go down), a lower cap on CEO wakes, batched decider events. A cheaper tier cuts usage burn and the price-weighted share, not the token share (PR3-13). CEO wakes are capped at 2 per active hour (proposed); non-urgent reasons batch into one wake per 30-minute tick and notices go to the board and digest.

6. Who decides: seven prompts, Jev for closed questions, code for everything else

Principle. The nesting lives in the node tree on disk. Deterministic code calls a fresh session at each event, with a brief assembled from a template, the frame slice, the node’s state and its packs. Prompts never call prompts.

6.1 Prompt inventory

Every brief also carries the frame slice and the packs, within its role’s size budget (s3.3).

8. The harness improves between runs, never within one

Ruling 8: long-run improving long-run is recursive self-improvement. R3 (research-self-improvement.md): working loops separate the proposer, a frozen evaluator and a kept rollback version; failing loops grade themselves. A run improves the work, never the rules.

  • Level 1 (M18): the harness is frozen per run (freeze_copy); one change per version; rollback by re-pinning; every confirmed HARNESS-FAULT becomes a regression test; stress_run.py catches busy loops (F-53). Meter integrity (M19) is a prerequisite: deduplicated events, bucket tags, an active clock, every pane metered (F-85 to F-88).
  • Level 2 adds the outer loop: an LLM proposes one change with a falsifiable prediction; a frozen replay gate outside the harness’s write scope; Rowan merges defect fixes, Jaime rules changes to done, thresholds, Jev or the evaluator.
  • Level 3: epochs (weekly, proposed): the daemon drains and restarts on the new pinned version (F-68).
  • Prompts and packs are the parameters (M27). The tunable set is the role templates (s6.1), the packs (s3.3), Jev question text and thresholds, and governor thresholds and caps. The loop itself (TRSC, the ladder, the merge queue) is not tuned. Each launch event records the prompt hash and the pack ids, hashes and token counts that session saw, so an outcome is attributable to what each session loaded (PR3-9; level 1). Tuning changes one parameter at a time between runs, scored by a frozen evaluator on a held-out goal, as in DSPy-style optimizers and skill-autoresearch; it starts at level 2.
  • Within a run only the plan adapts: the ladder, a run-scoped lessons file that dies with the run unless promoted (F-72, F-92), and longrun set within declared ranges.

AGENTS.md “self-anneal” is live repair inside a run, which SPEC s18 bans (agenda item 11). The “Do Better” source was not found (agenda item 12).
