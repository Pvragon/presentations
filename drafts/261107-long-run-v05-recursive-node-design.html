1. One page: one recursive node replaces the run, done is a frozen matrix version, and code forces the reframe

What changes. A v0.4 run is a flat queue under a CEO who judges its own convergence. v0.5 uses one primitive at every level, the node: a frame slice, finite exit tests, a budget and one procedure (Test-Recognise-Split-Commit, TRSC), done when its own tests pass. Nodes form a persistent tree per product. Levels 1 to 4 of Jaime’s ladder form the frame, written breadth-first and capped; level-5 tasks are decomposed as work meets reality. Done for release N is coverage-matrix version N, its expected results from an external oracle; one walk runs before acceptance. A code governor and each node’s budget rule escalate to an independent decider whose verdict binds. Code assembles each session’s role and domain packs. Landings verify in parallel in a merge train, because execution speed is a core metric (Jaime). Coordination is capped at 20-40% and watched by signal G6; build-side waste by efficiency signals (s5.8).

Why. On the eleven v0.4 runs of 10-30 to 11-06, second-pass rework took most of the spend (261106-lr04-week-watch/SYNTHESIS.md s2): strength spent 87% of component tokens on 112 reopens; finish built 15 subprojects in 5.3 h, then reworked for 34 h; no pass managed the architecture (CO-01).

What it fixes. All 105 inventoried failures map to a mechanism or “not addressed” (s13). A replayed governor fired 11 to 19 h before anyone noticed (s5.4). Coordination is an estimated 16% of a level-1 run, usage-weighted, with the limits adopted here, against 33% to 55% measured on v0.4 (s5.7). Waste inside build, an estimated 31-40% of one measured session that G6 missed, is caught by s5.8. First detection of non-convergence is estimated at 2 to 2.5 active hours and a binding reframe at 5 to 6, so the 3-hour target holds for detection only (s5.3).

2. The node primitive: frame slice, exit tests and budget, run through TRSC

2.1 Anatomy

frame_slice Capabilities, contracts and rulings touched; only the ancestor tests its outputs feed.

A node is a record on disk; a product’s nodes form one product tree in its repository, kept across runs (M25). longrun start takes a product and a node, never a plan file. A brief carries the frame slice and packs, never a transcript.

2.2 TRSC, one procedure at every level

From research-goal-decomposition.md (TOTE, Soar, ADaPT, ReCAP).

  1. Test. Run the exit tests; all pass is done. On first entry, freeze goal, why, tests and budget. This is strategic planning and always runs.
  2. Recognise, in code. A node the plan marks as a leaf (a skill, a prior method or one owner), and every red cell of a node that has an owner, goes straight to an owner with the cell and the frame slice. No Claude call.
  3. Split (no leaf is marked, or an owner’s attempt leaves the same cells red, which the budget rule sends to rung 2). Children come from failing tests. Code checks the WBS 100% rule, at most about 5 children, one parent integration test, and that each child names a frame capability.
  4. Commit. Specify only the next child; siblings with disjoint files and frozen inputs may run in parallel. An input is frozen only when its producer’s exit tests pass; Commit checks this in code before a consumer starts (F-35).

2.3 Frame eager, tasks lazy, and the frame’s size budget

DIRECTION s4: levels 1 to 4 split eagerly at Test; level-5 tasks split only on impasse. Eager is not deep: levels 1 to 4 go only far enough to name every capability, data source, central process and contract. Caps (proposed): frame about 300 lines; about 12 capabilities of about 15 lines; contracts as interface signatures. Intake refuses a frame over budget, in code (v0.3’s specs grew sixfold in a day).

2.4 Rules the node carries

  • Done is its own tests. Closed children under a failing parent test yield one new child per failing test. Integration is the parent’s exit test.
  • Fix path. Code routes a failing test to its node’s owner with the test and the frame slice: no spec rewrite, no routing session.
  • Budget rule, the single stuck trigger: spend past budget, or 2 cycles (fix wave plus matrix run) with no new test passing, triggers rung 2; spend past twice the budget (four times the estimate) is rung 4. Estimates include spec time and real capacity (F-25).
  • Planning rules, prompt text at level 1: real data first, with performance and subset-rerun tests (F-17, F-30); one owner per file; code on fixtures; FS, SS, FF or SF timing; never drop a node owning a matrix cell; a report is not an exit (F-96).

3. The frame holds the whole: brief slices, split checks, a decider checklist, pull-up and an architecture pass

Ruling 1: someone must hold the whole vision. The CEO’s memory failed at it, so the frame holds it:

  1. Every brief carries the frame slice (M1).
  2. Every split is checked in code (M2): each child names a capability; each test names the capability or contract it verifies, so a frame change flags only the tests on what changed (F-82).
  3. Decider checklist mode (M4). On every release, every 8 active hours (proposed) and in every reframe verdict, the decider answers a checklist that can fail (every capability serves the want; every red class has an owner; no contract changed outside a ruling; the frame is in budget). A failed item is a rung-4 trigger.
  4. Pull-up (M3; ruling 2). When red cells share a class key (Deckwright: the effect-class row) at 3 or more places in at least 2 nodes (G4), code moves the fix to the lowest node owning that class; no owner is a rung-4 trigger, and the decider adds the central process.

The architecture pass (M5; ruling 9). Every pass at levels 3 and 4 starts from the modules, one contract per pair, and where each kind of interpretation may happen; a product translating an external format inventories its whole construct set at intake. Exit tests, because an instruction alone failed (CO-01): each kind of interpretation is owned by one module; every census construct maps to an owning node. The check finds where the data is read, not a syntax: an AST rule lists every read of the raw card-text field and every parse call site, and each must route through the schema module, so text read with in, .split() or a dict keyed on fragments is caught as surely as a regex (close-out had ~130 regex sites on card text and 98 of 138 trigger modes unnamed). Every level-3 and level-4 architecture test runs on every landing, level 5 included, in the merge train at zero tokens (PR3-4); the gate reviewer adds LLM judgment only on level-3 and level-4 landings.

Architecture tests ratchet. At intake the daemon records each test’s violation count as its baseline. A landing fails only if it raises a count above the baseline; the baseline drops as violations are removed and never rises; the owning architecture child, or the adapter child, exits only at zero. On Deckwright the card-text test starts at about 130: a neutral landing passes, one that adds a read fails, and the refactor child drives the count down. Without the ratchet nothing lands on day one (F-05).

Contracts without pinning. Contracts are signatures frozen as children’s exit tests (F-21), unversioned, since pinning means two live implementations (F-15). A producer lands with every consumer’s tests green or, for many consumers (the card schema has eight, F-11), behind a temporary adapter whose child exits only when “the old interface has zero callers”. Sign-off: Jaime signs frame levels 1-2 at launch and on expansion in his runs; the decider signs 3-4 against the register before spend (F-84).

3.2 Expansion re-entry: re-test first, keep history

Finish copied strength’s boundaries and never asked whether X’s architecture fit X+Y+Z (F-14, F-11, F-28). In v0.5 “do Y and Z” re-opens a node of the same product tree (M24, M25). expand runs only on a decider classification and refuses a CEO-issued call or a node with an active governor signal (replanning, cooldown, an unresolved trigger, a pending verdict or hold). The strategic planner re-runs Test: (1) ground on the built code and data, not the old plan; (2) re-test, then rewrite only what fails: a passing part keeps its ids (F-82), a failing architecture test makes an architecture change the first child, and the rulings register carries over (F-84); (3) X’s accepted cells become regression cells, queued N+1 cells enter first, then Y and Z (F-36), with expansion scope ruled apart from the 10% budget; (4) signal windows and spend carry; (5) sign-off as at launch.

3.3 Context packs: every call gets a role pack and a domain pack, assembled in code

The staged-thinking study (../../sources/summaries/2610-internal-staged-thinking-study.md, 14 episodes) found that success tracked the domain’s own intermediate levels (Waystar: GET, CLEAN, ANALYZE, PUBLISH); a generic breakdown failed (F-13, F-19, F-20). So every call’s context has four layers (M26): core (AGENTS.md, lenses); a role pack (how to do one kind of work: architecture planning, coding, analysis, research, strategy and so on; a small universal set); a domain pack (the single source of the domain’s natural levels, which are the Split template, lens ids, oracle style and reference budgets); and the project’s grounding store, which links to pack entries and never copies them. The strategic planner tags each capability with a domain at intake; the daemon assembles every brief through a pack manifest (reusing find-skill); no model picks a pack at level 1.

  • Launch rule, in code: a child node cannot start without its role and domain packs. Intake’s Ground step, and an expansion’s into a new domain, runs on the generic pack and outputs the starter pack, signed with the frame (PR3-1).
  • Start budgets per role (Rowan’s starting values on Jaime’s delegation). Each role’s target is its measured v0.4 start plus its pack budget, in absolute tokens (review 2, probe A: first-turn context of every v0.4 session). A fresh go session (median 63,375 tokens) is a different session, since workers launch with --setting-sources project,local; it stays only as the ceiling for judgment roles. 3.4 Branches never overlap: ownership by design

Approved by Jaime, 2026-11-08: “great, approved on your plan for 1-6”.

Jaime (11-08) asked how branches avoid v1 and v2’s merge burden. Conflicts surfaced only at merge (F-65), builders wrote outside their files (F-66), shared files had split owners (F-16), and hot files drew the rework. Code prevents overlap on existing paths, with no new role:

  1. Ownership is designed in the architecture pass (M5). The frame maps each module to exactly one capability. A shared hot file is split by design (a registry becomes one file per capability plus a generated aggregate) or given exactly one owner.
  2. The split check verifies disjoint write-sets (M2). Each child declares the files it will write; any overlap is refused, and the fix is to sequence the children or fold them into one.
  3. The guard enforces ownership at write time (lr/guard.py, carried). An owner writes only its declared files. A refused write becomes a request to the file’s owner or a decider-ruled re-split, never a quiet edit.
  4. Conflict prediction. Every daemon tick runs git merge-tree across in-flight branches and merge-train candidates; a predicted conflict holds the later branch before more work stacks on it.
  5. Shared interfaces change only through their owner, by pull-up or an architecture child with the temporary adapter; consumers never edit a shared contract.
  6. Conflicts and cross-owner touches are counted on the board, each logged as a planning defect against the split that allowed it, and feed G7.

4. Done is matrix version N; one walk runs before acceptance

Ruling 3: done is a frozen executable condition; walks are discovery.

The coverage matrix (M7): one cell per effect class times modifier (Deckwright). A cell is data (input, expected result) run by a runner the interface’s node owns, so a refactor changes runners, never the protected expected results. One check, one owner, local assertions (198 of 252 close-out red checks were misreads, CO-07). Gates are named from owned files (F-05); stretch bars live in probe nodes (F-09). Done for release N is matrix version N, frozen when N’s build starts.

Matrix version 1: external oracle, size cap (PR3-11, review 2). Expected results come from an external oracle, never from the owners who build against them: for Deckwright, judge rulings per card (Scryfall) and official sources, per the coverage-matrix answer in 261104-deckwright-finish-findings.md s0. Each cell records its source. The strategic planner writes the cell schema and class list; the matrix-v1 planning node, with its own budget, authors the cells; the decider checks them before freeze (5 per class, proposed) and refuses a cell with no source. At most 300 cells for version 1 (proposed): finish’s 44 hard-part problems fell into about 17 classes, so 300 cells gives each class about 15 modifiers with room for classes no walk has hit, while authoring stays within one node’s budget and the full matrix within its 15 minutes (s9). Intake refuses a larger matrix.

The loop (M9): run every cell; one batched fix wave on red cells, by package, on the fix path; verify each package as it lands (F-43); end each wave with the full matrix (close-all round 6 went from 25 to 342 red without a sweep, F-42). A cell closes only if it failed before and passes after (F-07). One wave per node at a time (F-46).

Acceptance of release N (M8; Rowan’s rulings of 11-07): (1) matrix version N passes; (2) one walk runs on N’s built artifact, uncapped, full list to a file, its brief generated from the frame so the CEO cannot steer it (F-03; v0.4’s 5-problem cap was hit by 21 of 29 finish walks, and one uncapped pass found ~157 root causes); (3) one decider session triages the list, with the nearest existing cell per finding (code retrieval):

Finding Goes to
(a) An existing cell’s test is wrong Fixed in N on the fix path; corrected cells re-run in one final wave ending in the full matrix; the walk is not re-run. An architecture fix goes by pull-up, holding N for at most that node’s budget; then the decider rules accept with known failure (cell to N+1, named in release notes; never a hard-part cell) or hold, which is a rung-4 reframe of the owning subtree, after which N’s acceptance is re-evaluated.
(b) A new class A top-priority cell of N+1; never blocks N. A hard-part (b) finding is named in N’s release notes and is a checklist item (“is the census incomplete?”).
(c) Which is which The decider confirms each; the CEO cannot reclassify; duplicates merge.

(4) The decider accepts N when the corrected cells and full matrix pass; never the CEO.

Why done converges. Class (a) is bounded by N’s cells, one walk’s list and the owning node’s budget; (b) never touches N.

Scope budget. N+1 may add at most 10% of N’s cells (proposed); no “later” bucket (72% of strength gaps went there and were never built, F-36). Overflow means the enumeration was wrong: a rung-4 trigger. Deckwright’s first uncapped walk will likely overflow it.

5.3 Signals, defined on v0.5’s own events

Signals are computed from daemon events every 30 minutes over a 3-hour active-clock window (silences over 1 h cut out). G3 and G4 also evaluate per active hour, whichever fires first, so a slow wave cannot hide a stall.

# Signal Replaces Starting threshold (unfitted) Status Rung
G1 Exit-test pass trend per node S1 flat over 2 cycles folded into the budget rule 2
G2 New-cell rate per walk, share of matrix S6 not falling across 2 releases recorded from level 1; fires from level 2 4
G3 Fix yield: cells turned green over red at wave or hour start, net of regressions S4 under 0.5 for 2 waves; under 0.25 for 2 hours from the wave’s first landing live 2, then 4
G4 Repeat-class count: red cells sharing a class key S5 3 places in 2 nodes live 3
G5 Spend against budget new past budget; twice is rung 4 folded into the budget rule 2, then 4
G6 Coordination share, usage-weighted, strict (s5.7), cumulative after 10M and over the rolling window new notice over 30% on either; cumulative over 40% twice live notice, then 4
G7 Throughput: median verify time, landings per hour new median over 5 minutes, or landings under the plan’s rate live 3

G6 and G7 are run-wide. Any rung-4 trigger wakes the decider; rungs 2 and 3 are code. Notices go to the board and Jaime’s daily digest, never waking the CEO (F-51). Onset is the first hour or wave that fails to reduce red cells, or the first walk adding more new cells than the last.

Expected detection time (an estimate under s9’s bounds, a fix wave of about 1 active hour). G4 fires at the first full matrix showing a repeated class, about 1 h in (rung 3). G3 fires after two weak hours plus up to 30 minutes of clock lag: first detection at 2 to 2.5 active hours, so the 3-hour target is met for detection. A binding reframe adds the re-plan, one cooldown cycle, two more weak hours and the decider’s 1-hour hold: about 5 to 6 active hours, which does not meet 3 hours; level 1 refits the cooldown.

5.4 What the v0.4 backtest shows, and what it does not

governor-backtest.md replayed six old signals over 10 logs: fires 11.1 h before strength’s first stop and 35.0 h before Jaime’s call on finish, r2-r4 missed, none on four healthy runs. The thresholds do not carry over (grid edge, nothing held out); level 1 refits only what gets enough data (s12).

5.5 Binding verdicts and halts

  • The decider returns continue, re-plan X, pull up to Y, or reframe level k. A reframe names the work it removes or redraws (F-80); the daemon diffs the frame’s capability-to-module map and contract set before and after and refuses an id-only diff, so a relabel (finish’s C21, C22, C24 re-cut as SP1, SP2, SP5) cannot pass (F-14).
  • The verdict binds (M11): the daemon stops dispatching work it touches; running gates finish.
  • Holds run on the wall clock: verdict within 1 h, the CEO’s action within 2 more (proposed); past either, the daemon notifies Jaime and relaunches a dead CEO.

5.6 Seat duties the daemon owns (M20)

A deaf CEO pauses launches (F-58); every wake line is delivered (A-5). Rotation carries the live conversation (F-83, CRITICAL): the handoff holds the turns since Jaime’s last message, the open plan and unrecorded rulings, recorded first; no rotation mid-exchange. Pause holds launches, not running gates (F-104); a live ruling that changes a running gate’s tests aborts it, and aborted is not a failure (F-105).

5.7 Token buckets: planning is an investment, coordination is capped

Jaime (11-07) splits run tokens three ways. The daemon tags every session at launch; no model decides.

Bucket Holds Budget
Build owners building and fixing leaves the rest; waste inside it watched by s5.8
Planning investment strategic pass, Ground and grounding research, node specs and exit tests at first Test, matrix-v1 authoring, pack building 15% of usage-weighted run tokens, ceiling 20% (proposed; refit at level 1)
Coordination CEO, dispatch, decider events, gate reviews, retries, any re-plan or re-spec after a failed plan, and rework: fix-path sessions on a cell green earlier in the release 20-40% (Jaime); level-1 target 30%

Planning “pays dividends” (Jaime), so it is judged after each release by rework share (fix-path tokens on cells that went green to red, plus re-plans, over the release’s tokens); two releases at the ceiling with rework not falling is a checklist item. Re-planning after a bad plan is always coordination.

Tagging by prompt and trigger (PR3 s5): owner.md is build, except coordination on a fix path to a cell green earlier in the release or, retagged at the verdict, on a node a reframe removes; planning on matrix authoring. planner.md and spec_writer.md are planning at intake and first child, coordination after a failed attempt or a reframe. ceo.md, decider.md, walker.md, gate_reviewer.md and every retry are coordination. Each launch event carries bucket, packs, prompt hash, cache mode and model; the board shows coordination strict and lenient (owner-brief packs either way), planning and rework share live.
