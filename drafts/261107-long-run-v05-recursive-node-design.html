Draft for Jaime, governed by FRAME.md (D1 to D9). Document v0.4.0 answers ponytail-review-design-2.md (s15); it describes harness long-run v0.5, and “v0.4” alone means harness v0.4.21. “Estimate” is unmeasured; “proposed” is a starting value for Jaime to accept.

Terms. Daemon: the Python process that runs the loop; it spends no tokens. CEO: the Claude Code pane that launched the run and makes judgment calls. Owner: a session that builds one piece of work. Walk: a session that uses the product as its user would and lists problems. Reopen: v0.4’s resend of landed work through spec, review, build and gate. Decider: a fresh-context session that rules as Jaime would from the frame, the rulings register and an evidence pack, never the CEO’s transcript. Product tree: a product’s persistent tree of nodes (s2.1). Jev: TypeSafe’s typed decision model. F-NN: a row of failure-inventory.md; M-NN: a mechanism (key in s13); A-NN: a finding of ponytail-audit-v04.md; PR-NN, PR2-NN: findings of the first and second ponytail reviews; G1-G5: signals (s5.3); J1-J7: Jev placements (s6).

1. One page: one recursive node replaces the run, done is a frozen matrix version, and code forces the reframe

What changes. A v0.4 run is a flat queue under a CEO who judges its own convergence. v0.5 uses one primitive at every level, the node: a frame slice, finite exit tests, a budget and one procedure (Test-Recognise-Split-Commit, TRSC), done when its own tests pass. Nodes form a persistent tree per product; a run activates a subtree. Levels 1 to 4 of Jaime’s ladder (want, capabilities, data sources, processes and architecture) form the frame, written breadth-first and capped; level-5 tasks are decomposed as work meets reality. Done for release N is coverage-matrix version N; one walk runs before acceptance. A code governor and each node’s budget rule escalate to an independent decider whose verdict binds. Only the daemon records protected rulings; only the decider classifies requests and picks where an expansion re-enters.

Why. On the eleven v0.4 runs of 10-30 to 11-06 the second pass was the run (261106-lr04-week-watch/SYNTHESIS.md s2). Strength: 87% of component tokens went to 112 reopens; 0 of 26 walks passed. Finish: 15 subprojects in 5.3 h, then 34 h of rework. The control plane ran 22% to 47% against a 20% cap (F-51). Close-out landed 0 of 5 in 16 h; no pass managed the architecture (CO-01). Root causes: done held an open critic; every fix re-ran the new-work pipeline; later scope joined the queue unframed; the CEO judged its own convergence (F-03).

What it fixes. All 105 inventoried failures map to a mechanism, a deferred one, or “not addressed” with a reason (s13). A replayed governor fired 11 to 19 h before anyone noticed (s5.4); thresholds are unfitted, token savings an estimate. Proof goes level by level (ruling 7).

2. The node primitive: frame slice, exit tests and budget, run through TRSC

2.1 Anatomy

Field Content
id, level, order Identifier, ladder level 1 to 5, position among siblings.
goal, why The goal, and the parent objective it serves (Keeney).
frame_slice Capabilities, contracts and rulings touched; only the ancestor tests its outputs feed.
exit_tests Finite, mechanical or for a named judge; each names the capability or contract it verifies.
budget Tokens, active hours, money; 2x the estimate until a reference class exists (proposed).
state open, running, replanning, done.
children The committed child, fully specified, plus one-line stubs.
status_line 40 words: tests passing, top failing classes, spend, escalations. A board row.

A node is a record on disk. A product’s nodes form one product tree, stored in the product’s repository and kept across runs (M25). longrun start takes a product and a node, never a plan file, so later work always has a root to re-enter. A brief carries the frame slice, never a transcript (a few hundred lines at any depth, estimate).

2.2 TRSC, one procedure at every level

From research-goal-decomposition.md (TOTE, Soar, ADaPT, ReCAP):

  1. Test. Run the exit tests; all pass is done. On first entry, freeze goal, why, tests and budget. This is strategic planning and always runs.
  2. Recognise. If a skill, prior method or one owner closes the node, it is a leaf the daemon runs.
  3. Split (Recognise fails, or a leaf fails). Children come from failing tests. Code checks the WBS 100% rule, at most about 5 children, one parent integration test, and that each child names a frame capability.
  4. Commit. Specify only the next child; siblings with disjoint files and frozen inputs may run in parallel.

2.3 Frame eager, tasks lazy, and the frame’s size budget

DIRECTION s4: levels 1 to 4 split eagerly at Test; level-5 tasks split only on impasse. Eager is not deep: levels 1 to 4 go only far enough to name every capability, data source, central process and contract. Caps (proposed): frame about 300 lines; about 12 capabilities of about 15 lines; contracts as interface signatures. Intake refuses a frame over budget, in code (v0.3’s specs grew from 1,531 to 9,770 lines in a day).

2.4 Rules the node carries

  • Done is its own tests. Closed children under a failing parent test yield one new child per failing test. Integration is the parent’s exit test.
  • Fix path. A failing test goes to its node’s Recognise step: an owner, the test and the frame slice, no spec rewrite.
  • Budget rule, the single stuck trigger: spend past budget, or 2 cycles (fix wave plus matrix run) with no new test passing, triggers rung 2. Estimates include spec time and real capacity (F-25).
  • Planning rules, prompt text at level 1: real data first, with performance and subset-rerun tests (F-17, F-30); commit order respects frozen inputs (F-35); one owner per file; code on fixtures, data on its pipeline; FS, SS, FF or SF timing in the plan; policy holds are scheduler rules; never drop a node owning a matrix cell; a report is not an exit (F-96).

v0.4’s intake becomes the root’s Test, subprojects its eager Split, a reopen the fix path, add a request (s3.1).

3. The frame holds the whole: brief slices, split checks, a decider checklist, pull-up and an architecture pass

Ruling 1: someone must hold the whole vision; the CEO’s memory failed at it on every run, so:

  1. Every brief carries the frame slice (M1).
  2. Every split is checked in code (M2): each child names a capability; each test names the capability or contract it verifies, so a frame change flags only the tests on what changed (F-82).
  3. Decider checklist mode (M4). On every release and every 8 active hours (proposed) a session answers a checklist that can fail: every capability serves the want; every red class has an owning node; no contract changed outside a ruling; the frame is in budget; no running node traces to nothing. A reframe verdict session answers it too. A failed item is a rung-4 trigger.
  4. Pull-up (M3; ruling 2). When red cells share a class key (Deckwright: the effect-class row) at 3 or more places in at least 2 nodes (G4), code moves the fix to the lowest node owning that class. No owner is a rung-4 trigger: the decider rules a reframe adding the central process (“Forge construct encoding”, exit test “every construct in the grammar parses”).

The architecture pass (M5; ruling 9). Every pass at levels 3 and 4 starts from the modules, one contract per pair, and where each kind of interpretation may happen; a product translating an external format inventories its whole construct set at intake. Exit tests, because an instruction alone failed (CO-01): each kind of interpretation is owned by one module (import-graph or grep check); every census construct maps to an owning node. Close-out had 98 of 138 trigger modes unnamed and ~130 regex sites on card text.

Contracts without pinning; adapters with a deletion test. Contracts are signatures frozen as children’s exit tests, never work items with edges (F-21). No versioning: pinning in one repository means two live implementations, which was F-15. A producer change lands only with every consumer’s tests green (consumers from plan.py’s needs), or with the consumer change. Where an interface has many consumers (the card schema has eight, F-11), the producer lands behind a temporary adapter for the old interface (a shortcut: comment); consumers move one landing at a time and the last deletes it. Every architecture child carries the exit test “the old interface has zero callers” (grep), so it cannot be done while the adapter has callers.

Sign-off. Jaime signs off frame levels 1 and 2 before launch and on every expansion in his runs (s3.1); the decider signs off 3 and 4 against the register before spend (F-84).

3.1 Requests and expansion: the CEO proposes, the decider classifies and picks the node

A request, from Jaime or the CEO, during or after a run, is a proposal: the CEO may suggest a class and a node, never decide them (M10). One decider session classifies it and picks the re-entry node, given code evidence: the capability ids it touches (from test ids, M2), their lowest common ancestor, and whether it needs a new capability.

Class What it changes Re-entry node Ruled by
Priority change order only (code-enforced; budgets are threshold rulings) none decider classifies; CEO writes order
New scope cells under existing capabilities; may reframe levels 3-4 lowest common ancestor of the capabilities touched; its architecture tests re-run decider; 10% scope budget (s4)
Expansion the want or a capability (levels 1-2) owner of the highest changed level, usually the root rung 5, then s3.2

The task list is a derived view of the tree’s frontier, so there is no queue to append to (F-34). A goal the root does not cover is a want change at the root; another product gets its own tree. Business-scale intake is backlogged (my-lib/backlog/261107-long-run-goal-hierarchy-and-request-intake.md).

An expansion is rung 5. In a run Jaime owns he rules it: a ruling, not a notice. He is live, having just asked, so the CEO shows him the level-1 and level-2 diff in that exchange and the daemon records his typed reply (s5.2); “price tracker” comes back as “valuation history, not live market prices” before any spend. Only the new scope waits (an unanswered diff goes to his daily digest); the rest of the tree keeps working. In the ultra-long category Rowan rules via the decider path (level 3).

3.2 Expansion re-entry: re-test first, keep history

This week one product was split across three runs; finish copied strength’s boundaries and done-condition and never asked whether X’s architecture fit X+Y+Z (F-14, F-11, F-28). In v0.5 “do Y and Z” re-opens a node of the same product tree (M24, M25). expand is one code entry point, run only on a decider classification. It refuses a CEO-issued call (as the CLI refuses every protected kind), and refuses while the node or a descendant has an active governor signal: replanning or cooldown, an unresolved G3, G4 or budget-rule trigger, or a pending verdict or hold. That signal resolves by its own rung first, so an expansion cannot silence a governor. The re-entry node then re-runs its Test step:

  1. Ground on the built code and data as they are now, not the old plan.
  2. Re-test, then rewrite only what fails. Re-run the frame’s architecture exit tests and capability checks against the X+Y+Z goal and census. A passing part keeps its ids, so its cells are not flagged (F-82). A failing architecture test makes an architecture change the first child, under the adapter rule. The rulings register carries over; only the decider retires a ruling (F-84).
  3. Matrix. X’s accepted cells become regression cells; cells already queued for N+1 enter the new version first, then Y and Z (F-36). Expansion scope is counted apart from the 10% scope budget, sized by its own decider ruling, so walk overflow cannot be relabelled an expansion.
  4. History carries. Signal windows, first-fire counts and spend carry across; the budget grows only by the new scope, sized from the reference class. Only nodes the expansion creates start fresh.
  5. Sign-off as at launch: levels 1-2 by the rung-5 ruling, 3-4 by the decider.

4. Done is matrix version N; one walk runs before acceptance

Ruling 3: done is a frozen executable condition; walks are discovery.

The coverage matrix (M7): one cell per effect class times modifier (Deckwright), real cards and judge rulings as oracle. A cell is data (input, expected result) run by one runner per interface; the interface’s owning node owns the runner, so a refactor changes runners, never the protected expected results. One check, one owner, local assertions (198 of 252 close-out red checks were misreads; 71 were whole-pool rank checks, CO-07). Gates are named from owned files (F-05); stretch bars live in probe nodes (F-09). Done for release N is matrix version N, frozen when N’s build starts.

The loop (M9): run every cell; one batched fix wave on red cells, by package, on the fix path; verify each package as it lands (F-43); end each wave with the full matrix (close-all round 6 went from 25 to 342 red without a sweep, F-42). A cell closes only if it failed before and passes after (F-07). One wave per node at a time (F-46).

Acceptance of release N (M8; Rowan’s rulings of 11-07):

  1. Matrix version N passes.
  2. One walk runs on N’s built artifact, uncapped, full list to a file. The daemon generates its brief from the frame (want, hard part, every capability and its success lines); the CEO adds no text, so it cannot steer the walk (F-03). v0.4’s 5-problem cap was SPEC s9’s brevity cap: 21 of 29 finish walks hit exactly 5; one uncapped pass found ~157 root causes.
  3. One decider session triages the list, with the nearest existing cell per finding (code retrieval):
Finding Goes to
(a) An existing cell’s test is wrong: it passed but the product is wrong for that class Fixed in N, test and code, on the fix path; corrected cells re-run in one final wave ending in the full matrix; the walk is not re-run. A fix needing architecture work goes by pull-up to the owning node or a new architecture child, holding N for at most that node’s budget; then the decider rules accept with known failure (cell moves to N+1, named in N’s release notes; never a hard-part correctness cell) or hold.
(b) A new class, hard part or not A top-priority cell of version N+1. Never blocks N.
(c) Which is which The decider confirms each; the CEO cannot reclassify; duplicates merge.
  1. The decider accepts N when the corrected cells and full matrix pass; never the CEO (SPEC s8).

Why done still converges. Class (a) is bounded in size by N’s cells and one walk’s list, and in time by the owning node’s budget; (b) never touches N; no walk decides N. The hard part (Deckwright: “reads every card right”) is the cells on the hard-part capability; a wrong one is (a), never accepted with known failure. No false green is released unlabelled.

Scope budget. N+1 may add at most 10% of N’s cells (proposed). No “later” bucket (72% of strength gaps went there and were never built, F-36). Overflow means the enumeration was wrong: a rung-4 trigger. Deckwright’s first uncapped walk will likely overflow it (44 hard-part problems after finish).

5. A code governor watches convergence, and an independent decider rules

Ruling 4: detect non-convergence early (target 3 hours) and force a judicious reframe.

5.1 The escalation ladder

Rung Trigger Decided by

3 Pull up G4 code moves the fix to the owning node

One re-plan at a time (F-46). Rung 2 sets the node to replanning; the daemon refuses a second launch and skips its signals until the re-plan commits, then one cycle of cooldown (proposed); a later trigger is rung 4.

5.2 Ruling authority, enforced by the daemon

Ruling kind Author CEO
Change done: matrix contents, exit tests above level 5, walk triage class, accept with known failure decider or Jaime appeal
Change a threshold: governor, any budget, scope budget decider or Jaime appeal

Enforcement (M12). The daemon launches the decider and records its output; it is the only writer of protected rulings. The CLI refuses every protected kind from any session, so no session-role lookup is needed and v0.4’s --by jaime default (A-7) goes. A ruling by Jaime enters only as a verbatim quote from his own typed turn in the CEO session’s log. Claude Code stores tool output as type: "user" entries too (93 of 145 in one measured log), so the daemon accepts only user entries whose message.content is plain text or text blocks, with no tool_result block, no toolUseResult field and no isMeta flag, minus any wake line the daemon typed (it logs each). lr/guard.py denies tmux send-keys aimed at the CEO’s own pane. Appeals go to the same decider record; at most one per verdict, a second goes to Jaime’s daily review while the verdict stands.

5.3 Signals, defined on v0.5’s own events

Events: cycle_end, cell_red, cell_green, wave_end, walk_end, spend, verdict, ruling, appeal. Signals are ratios per node, computed every 30 minutes over a 3-hour active-clock window (silences over 1 h cut out).

# Signal Replaces Starting threshold (unfitted) Status Rung
G1 Exit-test pass trend per node S1 flat over 2 cycles folded into the budget rule 2
G2 New-cell rate per walk, share of matrix S6 not falling across 2 releases recorded from level 1; fires from level 2 4
G3 Fix-wave yield: cells turned green over red at wave start, net of regressions S4 under 0.5 for 2 consecutive waves live 2, then 4
G4 Repeat-class count: red cells sharing a class key S5 3 places in 2 nodes live 3
G5 Spend against budget new past budget; 2x is rung 4 folded into the budget rule 2, then 4

G1 and G5 restated the budget rule; G2’s single-release case is the scope budget. Dropped: S2 (moved with S1), S3 (tracks run size). Any rung-4 trigger wakes the decider; rungs 2 and 3 are code. Notices go to notices.log, the board and Jaime’s daily digest, never waking the CEO (F-51: notice-only wakes drove most of the overrun). Onset: the 3-hour target counts active hours from the first wave that fails to reduce red cells, or the first walk adding more new cells than the last.

5.4 What the v0.4 backtest shows, and what it does not

governor-backtest.md replayed six old signals over 10 logs. Two-signal fires: strength at 6.5 active h (11.1 h before its first stop), finish at 5.5 (18.9 h before the CEO’s note, 35.0 h before Jaime’s call); discovery, contract-invoice, waystar at 12, 5, 5; r2-r4 missed; none on four healthy runs. Per signal: S4, G3’s predecessor, first fired at 5.5 to 18 active h on four of six troubled runs; S5, G4’s, only on contract-invoice at 5.0 (full table in governor-backtest.md).

The signals fired early on troubled runs, but the thresholds do not carry over: fitted values sit at the grid edge, the healthy set gave 12 evaluations, nothing was held out. Level 1 refits only what gets enough data (s12).

5.5 Binding verdicts and halts

  • The decider returns continue, re-plan X, pull up to Y, or reframe level k. A reframe names the work it removes or redraws; instrument-only reframes are refused (F-80).
  • The verdict binds (M11): the daemon stops dispatching work it touches; running gates finish; untouched waves continue. A reframe’s new nodes have no history, so nothing re-fires at once.
  • Holds run on the wall clock (a halted run makes no events): verdict within 1 h of the fire, the CEO’s action within 2 more (proposed); past either, the daemon notifies Jaime, and a dead CEO is relaunched with the pending verdict. No decision waits on Jaime.
  • Forge night, replayed: G4 fires on one effect-class row across three nodes; no node owns construct encoding; the decider’s level-4 reframe removes the per-card tasks until “Forge construct encoding” exists.

5.6 Seat duties the daemon owns (M20)

A deaf CEO pauses launches after N minutes (close-out ran 9.7 h with a dead CEO, F-58); relaunch does not depend on the CEO; every wake line is delivered (A-5). Rotation carries the live conversation (F-83, CRITICAL): the handoff is built from the turns since Jaime’s last message, the open plan and unrecorded rulings, which enter the register first; no rotation mid-exchange. Pause holds launches, not running gates (F-104). A live ruling that changes a running gate’s tests aborts it; aborted is not a failure (F-105).

6. Decision models are replayed offline after level 1; code owns every decision

Code owns each decision and applies thresholds to Jev’s probability. Jev’s confidence is not calibrated (Banking77: 96.3% correct at 0.99 or higher, 29.6% below 0.5) and no labelled cases exist, so level 1 has no Jev code. At level-2 entry Jev is replayed offline on the event log; a placement goes live only past an agreement threshold Jaime sets. State sent is two summaries, never a transcript or a number comparison.

ID Closed question Answers Owning code Rule that decides (now, and when Jev is degraded) Status
J1 Is this walk finding the same class as nearest cell X? yes / no walk triage all of one walk’s findings, X attached, to one decider session offline replay
J3 Same class as an earlier failure? yes / no signal computer G4’s class-key rule offline replay
J4 After a failure: retry, fix, re-plan or escalate? one of four dispatcher 2 retries, fix path, rung 2 offline replay
J2 Does this child trace to a frame capability? yes / no Split checker code check level 2
J5 Does this change conflict with a ruling? yes / no / unsure ruling router decider; fail closed level 2
J7 Which model tier runs this unit? tier dispatcher tier table level 2

Ruling questions go to the decider first (F-59); duplicates raise the original’s priority (F-60). The CEO wakes only for its own rulings, appeal outcomes, Jaime, verdicts and releases.

7. The same node applies at three scales

7.1 Bounded build: finishing Deckwright

  • Root: “Deckwright reads every Forge card right and values it right.” Root tests are the matrix; the hard part is reading cards.
  • Frame: capabilities read, value, build decks; data: the 33,980 Forge scripts and the card database; architecture: Jaime’s three modules (card schema and query interface, card database, valuation and matrix), card text parsed only in the schema module. The construct census (138 trigger modes, 192 effect APIs) is an intake inventory; “Forge construct encoding” is a central process from the start.
  • Level 5: per-construct tasks split only when a cell fails.
  • First entry, not expansion. The v0.4 runs left no product tree, so level-1 run 1 creates Deckwright’s, grounding its Test step on the code as built; the three-module refactor is the first child, under the adapter rule. Import rule: a v0.4 check becomes a cell only if it meets the s4 cell rules (local assertion, one owner, real-card oracle); CO-07’s misreads and whole-pool rank checks are excluded, and what they aimed at is rewritten as red cells. Later Deckwright work re-enters this tree.

7.2 Multi-level product: billing reconciliation (the waystar shape)

Root “every claim dollar is attributed and published”, children ingest, attribute, publish. “Attribute every difference” is complex, so its children are time-boxed probes (waystar failed R1 three times, F-19; a planning rule at level 1, a node field from level 2). Data nodes run on real data from the first commit; code nodes on fixtures (F-33). The parent’s integration test (totals reconcile to source) is its done; performance and subset reruns are exit tests (full publish 2 h 17 m against 4 min for a subset, F-30).

7.3 Always-on goal: “you are the CEO of a printables business; earn as much revenue as you can” (Jaime)

  • Root: revenue, never done; children Product, Channels, Ops and fulfilment, Finance. A long run today is one subtree of this persistent tree.
  • Tests become metrics (Keeney): catalog, traffic and conversion are means objectives with targets raised when met for 2 epochs (Simon). Root reframe trigger: a means metric improved and revenue did not (CUSUM).
  • Parents read only compressed status (M14).
  • Money is in the budget; irreversible outside actions pass a guardrail gate (declared, capped in dollars, logged, new kinds ruled by Jaime). Human-gated account steps (ONE Mahjong: $0 revenue, 7 of 7 domains signed off) are external-dependency nodes owned by Jaime (F-26).
  • Expansion: “now add a second product line” re-enters Product, or the root if channels change too (s3.2); “Catalog line A” keeps its id because its tests still pass.
  • All of this is level 3; the portfolio bandit and frame decay stay unsolved.

8. The harness improves between runs, never within one

Ruling 8: long-run improving long-run is recursive self-improvement. R3 (research-self-improvement.md): working loops separate the proposer, a frozen evaluator and a kept rollback version; failing loops grade themselves. A run improves the work, never the rules.

  • Level 1 (M18): the harness is frozen per run (freeze_copy); one change per version after the first; the old version kept whole, rollback by re-pinning; every confirmed HARNESS-FAULT becomes a regression test (the rebuild’s 121 live-repair commits, P-63); stress_run.py at the week’s largest scale catches busy loops (F-53). A person reads the fault lines between runs. Meter integrity (M19) is a prerequisite: deduplicated events, spec writing as overhead, an active clock, every pane metered (F-85 to F-88).
  • Level 2 adds the outer loop: harvest in code; LLM cluster and propose (one change, a falsifiable prediction); a frozen replay gate outside the harness’s write scope; Rowan merges defect fixes, Jaime rules changes to done, thresholds, Jev or the evaluator; revert when real runs disagree; remove-the-signal test on gating LLM judges.
  • Level 3: epochs (weekly, proposed): at the boundary the daemon drains, checkpoints and restarts on the new pinned version; rollback is re-pin and restart. One daemon per STATE (F-68).
  • Within a run only the plan adapts: the ladder, a run-scoped lessons file that dies with the run unless promoted (F-72, F-92), and longrun set within declared ranges.
