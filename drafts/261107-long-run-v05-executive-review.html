A run goes from your goal to a release on its own

A planner turns the goal into cells, frozen before building starts. A small goal gets one builder (the single-builder layer, 1a). A big one splits into nodes that build in parallel (the splitting layer, 1b). Both end the same way: a walk, a run of every cell including the held-out ones, and a release decider who rules on the results.

Seven rules govern every run

No question waits on the owner. Code signs off the plan in the decider’s name and tells you. If the decider gives no valid ruling twice, code applies continue once for a crash, a block or a dead node, and otherwise ends the node. Governor alarms at their limit also go to the decider. Four events write STOP, which holds the run until you lift it: the spend cap, two safety-filter stops on a walk or release decider, a session on extended usage credits, and a third refusal of the split plan. Enforced by: ph_signoff, route_end, governor.exhausted; STOP by cap_tick, safety_route, finish, signoff_refused.

Frozen cells and the release decider judge done. At freeze, 10% of the cells (at least 5) are sealed from builders. If the decider has already seen some of them, you are told. A builder’s “done” ends only its session. A node lands only if the merge train finds its cells passing. A single builder’s landing checks its commits and artifacts and lets failing cells through. Before release, code runs every cell and gives the counts to the release decider as checklist items, so shipping with red held-out cells is its call (decision 2). Code refuses on an item marked failing or unruled, an untriaged walk finding, a serious finding on a core part, or a hold. A finding that a cell’s own test is wrong corrects that cell and buys one more build round. Enforced by: heldout.py, guard.check_read, verify.py, landing_verify, checklist_items, rule_release, route_a.

One owner per file. A split is refused if two children share a file or a parent’s file is left unowned. The single builder’s split is checked against every file tracked on its branch. A builder’s direct edits outside its files are blocked, and the merge train sends back any branch that changed a file its node does not own. Enforced by: split.split_problems, split.coverage_problems, split.tracked_coverage, guard.check_write, train.unowned_paths.

Every loop is bounded. Each kind of repeat trouble has a set number of tries, then one decider escalation. The ruling grants one more round. The next time the limit is reached, the node ends. Enforced by: bounded, grant_round (ROUND_GRANTS 1), node_end.

Spend and usage are capped. The default cap is 20M usage-weighted tokens. One gate holds every launch while STOP exists, or while usage is at its ceiling (98% of the plan’s limit) or cannot be read, and sends them when the hold lifts. Running sessions finish, so spend can pass the cap. lr5 resume [--cap N] lifts STOP and re-arms the cap at the spend plus N, by default one more cap. At the ceiling no usage probe runs until the window resets. A node session stops at its next hand-back after 3M weighted tokens since its node last landed, and is killed at 6M. Enforced by: cli.py (cap_weighted, cmd_resume), cap_tick, launch_held, ceiling_until, governor.e2.

Context is bounded per session. A node’s builder gets no new work past 250,000 tokens of context and restarts fresh at its next hand-back. A single builder rotates at 500,000. A second crossing after the grace period ends the build as outgrown, and in 1b the goal splits. Enforced by: governor.e1, update_gauge.

The run never goes silent. Each loop pass, the daemon revives any node that nothing alive or queued will move. A held launch waits under a key and goes out later. A STOP or usage hold that lasts 15 run-minutes is told to you once, with how to clear it. With no CEO pane, the daemon reads usage itself. Enforced by: revive_dead_nodes, node_life, retry_deferred, track_holds, refresh_usage.

A stuck node gets bounded tries, a ruling, then ends alone

In the splitting layer, a failing node ends alone and the run goes on to release. Only the top node, or one of eight run-wide causes (about the scope, cells, packs or sign-offs), refuses the run.

A failed node also fails any unstarted node that needs it first. The release record lists every failed node. Enforced by: revive_dead_nodes (DEAD_S 60, MAX_REVIVES 2), governor.budget, governor.exhausted, bounded (NO_LANDING_LAUNCHES 4), take_escalation, route_end, node_end (node_confined, RUN_WIDE), node_fail.

The live test passed every check except its planning limit

M1 attempt 7 built a Markdown knowledge-base toolkit. It ran from 22:55 PT on 2026-11-18 to 02:14 PT on 2026-11-19, 3.3 hours not counting holds for the usage limit.

Source: runtime/.tmp/261119-m1-attempt7-measure.txt. The other five pre-set limits passed. One planner session spent 1.73M of the 3.03M planning tokens. The design counts a second builder that shadows one node for comparison (the “standing twin”) as planning; without it the share is 32.8%, still a FAIL. During the night Rowan patched the harness four times (three code fixes and one missing reference file) and answered two builder questions. The earlier single-builder control used about a quarter of v0.4’s tokens per cell (4,172 against 17,098) and ran 2.4 times faster. It still ended in a refusal, because the safety filter blocked both walk sessions. Its official result was “build the second layer”. The two runs built different goals.

Fixes since the test pass the tests and two replays

The live run’s 13 defects are fixed. Of the register, R1 to R15, R18, R19 and R20 are closed, the skill instructions (R16) are pending, and R17 is the exit report. R20 added ownership checks at landing, bounded governor alarms, one launch gate for STOP and usage, a cap that re-arms on resume, hold notices and no probe at the ceiling. On the final code, main eb2ec74c, the full suite passed 759 of 759 tests in an independent run, and a second gate passed the register’s 148 tests and the suite twice. Both replays released, with zero stalls, hangs and owner waits; in the node-fail replay, node n6 failed and 26 cells were deferred. Sources: runtime/.tmp/261120-final2/.

Seven gaps remain open

  • No live run has used the fixed code. Replays use fake builders, so they say nothing about real cost or quality.
  • The M1 run’s harness copy lacks the node planner’s new split rule.
  • Only unit tests cover a blocked re-plan, a failure spreading to dependent nodes, a node revived after a granted round, a parent test no child owns, and every R20 path: the ownership refusal, the catch-all split check, a governor alarm ending a node, launches held by STOP or usage, the cap re-arm, the 15-minute hold notice and the skipped usage probe.
  • The 0.6 Sonnet factor is assumed, the usage reading uses an undocumented event, and the wall-time model failed and stands accepted by ruling.
  • Two corrected test cases were not re-measured live, and 10 prompt files changed since their last freeze.
  • Guard gaps: a commit typed in an inline Python block passes, and paths like $TMPDIR are not resolved.
  • Two held one-off launches of the same kind on one node keep only the later one; it is unconfirmed whether that occurs.

You decide nine things at the review

  1. Saturation per topic. Rowan’s default: the research check passes when every topic (a note’s topic: field, else its first folder under context/) with three or more sources got at most one new fact from each of its last three.
  2. Red held-out cells. The release decider rules on them today. Should code block a release instead?
  3. The standing twin. Should it count as planning? M1 fails either way; the ruling sets future reporting.
  4. Limit sizes. One extra round per ruling, four launches with no landing, two repair tries. No spec sets them.
  5. The default continue. Code applies it once per cause and node when the decider gives no usable ruling.
  6. A failed node ends alone. A pilot can release with failed nodes listed. You are told and nothing waits.
  7. Deliberate stops. Keep all four STOP events as stops you lift, or turn some into decider rulings.
  8. The next register. More than 20 findings are recorded and unworked. Choose which, if any, come first.
  9. Push. My-lib has 179 local commits not on origin/main (git, 2026-11-20). The push needs your go-ahead.

The pilot goal and its spend cap (20M usage-weighted tokens by default; M1 spent 8.47M) are also yours.
